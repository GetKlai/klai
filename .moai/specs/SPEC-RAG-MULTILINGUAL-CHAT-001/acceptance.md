# Acceptance: SPEC-RAG-MULTILINGUAL-CHAT-001

Given/When/Then scenarios for the multilingual-chat SPEC. Each scenario
maps to one or more REQs and is verified either by automated tests
(unit, integration, eval-suite) or by manual end-to-end verification
against a real tenant.

## Phase 1 acceptance (REQ-03, REQ-04)

### AC-EVAL-BASELINE — Baseline measurement on existing NL/EN data

**Given** the cross-lingual eval-suite from REQ-03 is committed
**And** the existing reference test data (NL/EN queries against
voys/support snapshot) is in place
**When** the eval-suite runs on CI against the **current** synthesis
system prompt (i.e. before Phase 2 lands)
**Then** the report contains per-language scores for faithfulness,
answer-relevance, and citation-correctness for NL and EN
**And** `language_correctness` is reported and is ≥ 95% for both NL
and EN
**And** these baseline scores are recorded as the floor for REQ-05's
post-change comparison.

Verified by: automated CI run, scorecard committed alongside the SPEC
in `.moai/specs/SPEC-RAG-MULTILINGUAL-CHAT-001/baseline-scorecard.md`
(generated during Phase 1).

### AC-EVAL-CROSSLINGUAL-COVERAGE — Eval-suite supports six languages

**Given** the eval-suite from REQ-03 is committed
**When** the test set is enumerated
**Then** at minimum 20 queries exist for each of NL, EN, DE, FR, PT,
ES
**And** each query has at minimum one corresponding reference answer
in the same language as the query
**And** the reference answers are generated by a stronger model than
the synthesis model (klai-smart if synthesis uses klai-fast).

Verified by: unit test enumerating the test set + asserting per-language
counts.

### AC-JUDGE-MULTILINGUAL — Judge prompt handles all five languages

**Given** REQ-04's multilingual judge is implemented
**When** the judge is asked to score a German response to a German
query
**Then** it returns a faithfulness score in [0, 1]
**And** it returns `language_correctness=True` because the response is
in German
**When** the judge is asked to score a German query that received an
English response
**Then** it returns `language_correctness=False`.

Verified by: unit test on synthetic fixtures (does not call the LLM).

## Phase 2 acceptance (REQ-01, REQ-02, REQ-05, REQ-08, REQ-09)

### AC-NL-NORM — No regression for Dutch users

**Given** the new system prompt from REQ-01 is deployed
**When** an existing voys-tenant user asks
*"Hoe stel ik RedCactus in met HubSpot?"* in chat
**Then** the response is in Dutch
**And** citations [n] point to Dutch source URLs as before
**And** the answer is at most 0.02 lower on faithfulness, answer-relevance,
and citation-correctness compared to the pre-Phase-2 baseline.

Verified by: automated eval run against existing NL test set;
production smoke test on voys.

### AC-EN-NORM — No regression for English users

**Given** the new system prompt from REQ-01 is deployed
**When** a getklai-tenant user asks the same question in English
**Then** the response is in English
**And** citations [n] point to whatever sources retrieval finds
(whether NL or EN)
**And** the answer scores within ±0.02 of the pre-Phase-2 EN baseline.

Verified by: automated eval run against existing EN test set;
production smoke test on getklai.

### AC-DE-NEW — German query against Dutch corpus

**Given** the new system prompt is deployed
**And** the voys/support corpus is Dutch
**When** a colleague asks
*"Wie konfiguriere ich RedCactus mit HubSpot?"* in chat
**Then** the response is in German
**And** the response cites the same Dutch source URLs that the NL
version would have cited (or a subset, if some chunks were not
retrieved cross-lingually)
**And** `language_correctness=True` is logged
**And** the response is coherent (judge faithfulness ≥ baseline − 0.02
on the cross-lingual eval set).

Verified by: cross-lingual eval suite + manual end-to-end test against
voys with a real DE colleague.

### AC-ES-NEW — Spanish query against Dutch corpus

Same as AC-DE-NEW, with query in Spanish:
*"Cómo configuro RedCactus con HubSpot?"*

**Caveat**: Mistral Small is documented weaker in ES. If
`language_correctness` < 95% or faithfulness drop > 0.05 vs NL
baseline, REQ-06 is triggered for any tenant whose primary language
is ES.

### AC-FR-NEW — French query against Dutch corpus

Same as AC-DE-NEW, with query in French:
*"Comment configurer RedCactus avec HubSpot?"*

**Coverage scope**: this scenario also serves Walloon-Belgian tenants;
Vlaams is covered under AC-NL-NORM since Vlaams ≈ NL for written chat.

### AC-PT-NEW — Portuguese query against Dutch corpus

Same as AC-DE-NEW, with query in Portuguese:
*"Como configurar o RedCactus com o HubSpot?"*

**Caveat**: Mistral Small (klai-fast) coverage of Portuguese is less
documented than EN/DE/FR. If `language_correctness < 95%` or
faithfulness drop > 0.05 vs NL baseline, REQ-06 is triggered for any
tenant whose primary language is PT.

### AC-MIXED-NL-EN — Single foreign word does not switch

**Given** an active NL conversation thread
**When** the user replies "thanks!" (English, single word)
**And** then sends another NL substantive question
**Then** the response to "thanks!" stays in NL (or is skipped because
"thanks!" is a non-question acknowledgement)
**And** the response to the next NL substantive question is in NL.

Verified by: unit-level acceptance test on synthetic conversation
fixtures; manual reproduction.

### AC-SUBSTANTIVE-SWITCH — Substantive question switches

**Given** an active NL conversation thread (3+ NL turns)
**When** the user asks a full-sentence question in English
*"Can you also explain how to integrate this with Salesforce?"*
**Then** the response to that question is in English
**And** subsequent substantive English messages stay in English
**And** subsequent substantive NL messages switch back to NL.

Verified by: unit-level acceptance test on synthetic conversation
fixtures; manual reproduction.

### AC-NO-DISCLAIMER — No source-language disclaimers

**Given** the new system prompt is deployed
**When** a German query produces a German answer citing Dutch sources
**Then** the answer body contains no phrases like "translated from
Dutch", "the source is in Dutch", "originally in Dutch", "as the Dutch
documentation says"
**And** the citation [n] format is preserved unchanged.

Verified by: regex check in the eval-suite over response bodies; manual
spot-check on 10 cross-lingual responses.

### AC-OBSERVABILITY — Logs and dashboard

**Given** REQ-08's logging is in place
**When** a chat completion fires
**Then** a structured log event with `event="chat_synthesis_complete"`,
`request_id`, `org_id`, `query_language_detected`,
`response_language_detected`, and `language_correctness` lands in
VictoriaLogs
**And** the new Grafana panel shows
`language_correctness` rate per language over a rolling 7-day window
**And** rates are ≥ 95% for all six target languages.

Verified by: manual VictoriaLogs query; Grafana panel screenshot
attached to the sync-phase PR.

### AC-EVAL-PASS — Phase-2 eval gate

**Given** Phase-2 (REQ-01, REQ-02) is implemented
**When** the cross-lingual eval-suite runs manually against the new
prompts
**Then** `language_correctness ≥ 95%` per language
**And** faithfulness, answer-relevance, citation-correctness are
within ±0.02 of the NL/EN baseline.

If the gate fails for any language, the implementer MUST either revise
REQ-01's prompt and re-run, or remove the failing language from the
target list with a HISTORY entry on this SPEC. There is no automatic
model-escalation fallback.

Verified by: manual eval-suite run; scorecard committed alongside the
sync-phase PR.

### AC-SHARED-LIBRARY — Prompt lives in klai-libs, nowhere else

**Given** Phase 2 has merged
**When** the codebase is grep-scanned for the prompt's opening line
*"[CRITICAL] Detect the language"*
**Then** exactly one occurrence is found, in
`klai-libs/chat-prompts/klai_chat_prompts/__init__.py`
**And** the previous in-file constants in `synthesis.py` and
`partner_chat.py` are absent (replaced by imports).

Verified by: CI lint run on every PR after Phase 2 merges; manual
spot-check at sync time.
